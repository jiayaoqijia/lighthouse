# EF qualification reporting

The old success message prints the number of all CaseResults as passed, even when a result is SkippedBls. A Rust test entry can also succeed without an enabled fork/feature. These are reporting boundaries, not evidence that all vector bodies executed. The selected source-generated Gloas corpus contains152 cases and no BLS-ignored metadata; existing real-HTTP/signed-transition evidence is retained. Fix report accounting and explicitly identify inactive handlers while preserving the actual validation, fixture selection and error policy.

The dedicated execution-envelope operation handler is currently disabled and the selected published release supplies no corresponding `operations/execution_payload` directory. It must be reported inactive, not counted as executed envelope coverage. Real signed HTTP/cache regressions, source-generated signed fork/transition cases and independent live-window BLS replay remain separate positive/negative consumers. Heze and model-only FCR/compliance fixtures are also outside the real-crypto Gloas receipt where disabled or tagged BLS2. This change does not enable missing fixtures or change validation/selection. Standard EF commands now expose successful per-handler output so skipped/empty/actual execution counts are reviewable.
