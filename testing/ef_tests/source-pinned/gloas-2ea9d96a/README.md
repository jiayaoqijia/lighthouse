# Source-pinned Gloas fork vectors

These vectors are generated by the unchanged Ethereum consensus specification at2ea9d96a420927eb1a35d7c9399c8b3691c69f6a (CC0-1.0), not by Lighthouse. The source archive and complete per-file SHA256 manifest are included. All44 minimal and42 mainnet cases compare complete SSZ states; the upstream generator excludes two large-validator tests on mainnet only. Both real-BLS Python generation runs pass86 cases and produce344 byte-identical files.

The inherited v1.7.0-beta.4 release predates this selected contract: its fork vectors retain all availability bits and older builder/validator key routing. Only the Gloas fork/fork suite is replaced. Existing full EF runs still execute every other fork, BLS backend and suite, and also run the direct source-pinned Gloas consumer. No expected state is derived from a failing Lighthouse run, and fork_upgrade is not skipped.

## Reproduction

Use Python3.14.4 in a fresh scratch directory. First run the installer with --verify-only to verify both original archives and all members. Extract consensus-specs-2ea9d96a.tar.gz into the scratch directory; its root is consensus-specs-2ea9d96a420927eb1a35d7c9399c8b3691c69f6a. Create a separate virtual environment, install generator-requirements.txt, then install that extracted package with --no-deps --editable. The original build dependencies are pinned in its pyproject.toml. Do not modify the operating qualification environment.

From that extracted source, run:

```sh
python -m pysetup.generate_specs --all-forks
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$PWD/tests/core/pyspec:$PWD" python -m pytest -q -n 4 --dist=worksteal --preset=minimal --preset=mainnet --reftests --reftests-output=/absolute/scratch/vectors tests/core/pyspec/eth_consensus_specs/test/gloas/fork
```

Hash every generated file and compare with manifest.json (the archive adds the leading tests/ directory). The clean-source second run is the packaged result. The pinned real backend is py_arkworks_bls12381==0.5.0. Source modules for minimal/mainnet Fulu/Gloas are separately fingerprinted in the manifest.

## Admission and consumer

`python3 ../../install_source_pinned_gloas.py --verify-only` checks both archives, exact member set, individual hashes and nonempty preset counts. Installation stages complete verified trees and rolls both presets back if publication fails. Its regressions reject changed source/archive/state bytes, unexpected paths and a forced second-preset publication failure before accepting unchanged fixtures.

`make -C testing/ef_tests` downloads the original full release and overlays only these verified suites. `cargo test --release -p ef_tests --features ef_tests,spec-minimal --test tests gloas_source_pinned_fork_upgrade` exercises the directly runnable minimal consumer; omit spec-minimal for mainnet. Real BLS is required; fake_crypto excludes this extra consumer and retains its existing full suite. Hosted full-suite outcomes and the steady-operation48h result are separate gates.
