# ETH2030 Lighthouse development

Use `eth2030` for ETH2030 consensus client development. The current upstream
baseline is Lighthouse unstable `8104a2467`. The March `feat/fix-native-aa` branch
remains the source of historical integration behavior and test scenarios.

## Historical changes retained

- `IFLOW.md` links to the upstream contributor guide for iFlow users.
- Heze self-built bids carry the inclusion-list committee bits for the same
  previous-slot list view used in their Engine payload attributes. The branch
  uses upstream's dependent-root keyed store and preserves that view across
  the asynchronous Engine request. The integration test exercises a list
  that becomes equivocated while the request is in flight.
- Heze bid gossip checks the previous-slot timely view under the parent's
  dependent root. A missing required bit causes the bid to be ignored
  before cache insertion.
- The VC reads Heze duties, requests a candidate from a BN backed by its
  execution engine, signs for the assigned validator, and publishes the same
  signed message to redundant BNs. The unsigned candidate endpoint uses
  the Bogotá transaction array result of `engine_getInclusionListV1`.

Upstream owns Gloas forkchoice, payload attestations, envelope processing
and retrieval, along with Heze list verification and storage. Continue
Heze list retrieval and Bogotá V6 validation and fork choice work against
the current draft contracts. The older list wire schema and Engine status
enum differ from those contracts.
[Heze inclusion lists](https://github.com/ethereum/consensus-specs/blob/313cbfe561517a81eb11607fea7c6985e562eaa9/specs/heze/inclusion-list.md) · [Bogotá Engine API](https://github.com/ethereum/execution-apis/blob/981aa66d79364be8322a9c358aaf0a571cca0873/src/engine/bogota.md)

## Native account abstraction

Hegotá schedules EIP-8141 Frame Transactions (type `0x06`) and EIP-7805
FOCIL. The historical Lighthouse commit `3b5fc06f6`, titled “complete
native account abstraction updates”, changes FOCIL state, gossip, validator
service and Engine glue. It provides no Frame transaction decoder.
EIP-7701 (type `0x05`) was withdrawn. Use EIP-8141 vectors and retain old
transactions as historical fixtures with their original draft version.
[Hegotá meta EIP](https://eips.ethereum.org/EIPS/eip-8081) · [EIP-7701](https://eips.ethereum.org/EIPS/eip-7701) · [EIP-8141 draft, 2026-11-01](https://github.com/ethereum/EIPs/blob/dc5d5fa688b7fe87b95a907fcc128b4fde2f4d2f/EIPS/eip-8141.md)

ETH2030 EL owns Frame transaction decoding, execution, authorization,
fee sponsorship and receipts. Lighthouse passes transaction bytes through
Engine. Its local versioned-hash verification also decodes transactions
through Alloy. At the integration baseline, the decoder rejects type
`0x06` and previously collected hashes only from type `0x03`. The fork's
Heze local verifier extracts Frame hashes alongside EIP-4844 hashes in
transaction order. It preserves the original transaction bytes for the
block hash and applies this path to historical envelopes and optimistic
finalized sync. EL-assisted Frame import requires the coordinated EL draft
implementation.
[Lighthouse versioned hash verification](beacon_node/execution_layer/src/versioned_hashes.rs) · [Historical envelope import](beacon_node/beacon_chain/src/historical_blocks.rs)

For the EL pairing, use the same Frame draft on both clients. The ETH2030
EL previously used a four-field frame and separate execution and blob fee
caps. The November draft uses frame flags and execution/state limits,
signature records, a shared fee budget and a bounded account nonce.
Include a sponsored
transaction with a canonical receipt and payer balance delta on both ELs,
and a blob-bearing Frame transaction whose hashes match the envelope
commitments. Keep FOCIL delivery and enforcement as a separate assertion.
The Bogotá devnet v2 fixtures predate the November nonce-boundary
revision. Match the vectors to the selected draft and add a boundary case.
[Bogotá devnet fixtures](https://github.com/ethereum/execution-specs/releases/tag/tests-bogota-devnet%40v2.0.0)
